# Explainable Anomaly Detection in Enterprise Authentication Logs

MSc Dissertation — a comparative evaluation of custom SIEM correlation rules, multi-feature
Isolation Forest, TreeSHAP attribution, and MITRE ATT&CK-aligned SOC triage intelligence,
applied to enterprise authentication behaviour.

Four detection layers are built and evaluated independently, then combined:
**SIEM Rules → Isolation Forest → TreeSHAP Explanation → MITRE ATT&CK Attribution.**

---

## Key results

| Metric | SIEM Rules | Full framework (IF + SHAP + ATT&CK) |
|---|---|---|
| F1 | 0.6069 | 0.7108 |
| False Positive Rate | 0.0123 | 0.0053 (69.7% reduction, McNemar p < 0.000001) |
| Mean time to triage | 8 min | 3 min |
| Analyst hours/day | 43.2 | 8.7 |
| Analyst confidence (/5) | 2.0 | 4.1 |

TreeSHAP explanation latency: 4.72 ms/alert. ATT&CK confidence-tier precision: 97.0% (HIGH) /
77.9% (CRITICAL) / 39.8% (MEDIUM-LOW).

## Setup

**1. Clone the repository**
```bash
git clone https://github.com/Oluwaseyimodel/auth-anomaly-detection-lanl.git
cd auth-anomaly-detection-lanl
```

**2. Create a virtual environment and install dependencies**
```bash
python -m venv venv
venv\Scripts\Activate.ps1        # Windows PowerShell
pip install -r requirements.txt
```

**3. Start MongoDB**
A local MongoDB instance is required for raw event storage. Install MongoDB Community
Server and ensure it is running on the default port before running `01_data_loading.ipynb`.

**4. Start Elasticsearch via Docker**
```bash
docker run -d --name auth-anomaly-es -p 9200:9200 -e "discovery.type=single-node" -e "xpack.security.enabled=false" docker.elastic.co/elasticsearch/elasticsearch:9.4.2
```

## Getting the raw data

The raw LANL authentication log (`auth.txt.gz`) is **not included in this repository** — the
full file is approximately 11.4 GB, well beyond GitHub's size limits.

1. Download the dataset from Los Alamos National Laboratory:
   **[https://doi.org/10.17021/1179829](https://doi.org/10.17021/1179829)**
   (Kent, 2015 — Comprehensive Multi-Source Cyber-Security Events)
2. Download `auth.txt.gz` and `redteam.txt.gz`.
3. Place both files in a `raw_data/` folder in the project root (create it if it doesn't
   exist — it's gitignored):
   ```
   auth-anomaly-detection-lanl/
     raw_data/
       auth.txt.gz
       redteam.txt.gz
   ```
4. `00_explore_lanl.ipynb` performs the Days 12–14 extraction and stratified sampling
   described in the dissertation (Section 2.2.6), producing the working 68,221-event dataset
   from this raw file.

## Running the pipeline

Run the notebooks in order, top to bottom. Each is a self-contained sprint stage and writes
its outputs (CSVs, charts) to the project root for the next notebook to consume:

```
00_explore_lanl.ipynb → 01_data_loading.ipynb → 02_features.ipynb →
03_siem_rules.ipynb → 04_isolation_forest.ipynb → 05_shap.ipynb → 06_evaluation.ipynb
```

## Running the dashboard

Once the notebooks have been run at least once (so the CSVs exist), launch the Streamlit
dashboard:

```bash
streamlit run app.py
```

Opens at `http://localhost:8501` with five views: SIEM, Isolation Forest, TreeSHAP, ATT&CK
Tiers, and an Integrated comparison across all four configurations.
